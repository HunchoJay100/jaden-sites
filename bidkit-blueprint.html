Core Features

What It Is

A full-featured construction estimating wizard that turns project dimensions into accurate bids with multiple export options.

⚙
Wizard

5-Step Estimation Wizard

Project Info, Dimensions, Structural Trades, Finish Trades, and Summary. Guided flow takes you from blank project to finished estimate.

★
Pricing

Pricing Engine

~130 editable rate constants covering every trade. Adjust any rate on the fly or reset to Flynn Development defaults.

⇢
Export

4 Export Formats

Excel workbook, branded HTML proposal, buildlist spreadsheet, and JobTread CSV. Every output you need, one click away.

💾
Persistence

Save/Load System

localStorage persistence keeps your work between sessions. Import and export full project backups as JSON files.

⚒
Calculations

Smart Calculations

Automatic computation of footer linear feet, slab cubic yards, framing complexity multipliers, and roof squares from dimensions.

⇄
Integration

JobTread Integration

CSV export maps directly to JobTread budget format with cost groups, cost codes, and built-in markup percentages.

V2 Rationale

Why Migrate

The current single-file architecture works, but has limits. Here is why V2 moves to a framework.

Scale

3,000+ Lines, One File

Impossible to maintain or extend. Every change risks breaking something elsewhere in the monolith.

Structure

No Components

Everything tangled together. Trade cards, wizard steps, exports, and state all live in one undifferentiated block.

State

No State Management

DOM manipulation everywhere. Data flows are unpredictable and hard to trace through the codebase.

Quality

No Tests

Zero coverage. Cannot verify that pricing calculations remain correct after any code change.

Tooling

No Build Pipeline

No linting, no minification, no optimization. No TypeScript for type safety on critical pricing math.

Ecosystem

Framework Ecosystem

Access to routing, dev tools, hot reload, and the entire npm package ecosystem for faster development.

V2 Decisions

Architecture Decisions

Key technology choices for the BidKit V2 migration.

Framework

Next.js or React+Vite

Framework selection still TBD. Both are viable. Decision depends on whether SSR/routing complexity is needed or if a lightweight SPA is sufficient.

Language

TypeScript

Type safety for pricing math. Every rate constant, formula, and output must be typed to catch errors at compile time.

Database

Supabase

Cloud persistence, same stack as RoofPact. Shared knowledge across projects, proven auth, and PostgreSQL under the hood.

Styling

Tailwind CSS

Consistent with other projects in the Flynn Development ecosystem. Utility-first approach keeps styles co-located with components.

Patterns

Component Library

Shared trade card pattern and reusable wizard steps. Build once, use across all 36+ trades with consistent behavior and styling.
